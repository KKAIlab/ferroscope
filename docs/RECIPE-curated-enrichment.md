# Recipe: curated enrichment of automated records

The automated layer only discovers: a record in `data/live.json` proves it matched a
search, and the site therefore shows it as "Evidence not assessed" with document type
"PubMed record" until a curated layer speaks for it. This recipe is the procedure for
that curated round — taking the highest-value automated records and giving them a real
reading. It is written for a session **with network access to publishers** (PubMed,
doi.org, journal sites); a sandbox that cannot open the primary source cannot execute
this recipe, and must not fake it.

## Inputs

- `docs/ENRICHMENT-QUEUE.md` / `docs/enrichment-queue.json` — the current work list,
  generated by `npm run build:enrichment` (and refreshed on a schedule by the
  "Build FerroScope enrichment queue" workflow). Regenerate before starting: the
  PubMed window moves, and a stale queue names records that may already have left it.

## Ground rules (the honesty contracts, applied to this round)

1. **Never write an interpretation of a source you did not open.** The validators
   enforce the file shapes, but only the reader can make `checkedBy` true.
2. **Reading depth bounds what you may write.** Abstract-only reading supports a
   document classification and a descriptive brief; an evidence grade or a paper
   reading record requires the figures.
3. **Unread stays unassessed.** Skipping a queue entry is always acceptable; grading
   one without reading never is.
4. **English only** in every published field — CJK is confined to the terminology
   corpus, and `npm run check:surface` enforces it.

## Per-record procedure

For each queue entry, in order (laboratory-watch matches first):

1. **Open the primary source** via the DOI link. Read the abstract; open the figures
   if the record looks like it warrants a grade or a paper record.

2. **Classify the document** — append to `data/record-overlays.json`:

   ```json
   {
     "canonicalId": "doi:10.xxxx/yyyy",
     "documentType": "original-research",
     "documentTypeBasis": "curated-audit",
     "documentSubtype": "",
     "evidenceGrade": null,
     "checkedBy": "<your identity>",
     "checkedAt": "YYYY-MM-DD",
     "reason": "Read the abstract and figure list at the publisher; primary data with a stated rescue design."
   }
   ```

   `documentType` must be one of the classes in `lib/records.mjs` `DOCUMENT_TYPES`.
   Set `evidenceGrade` (A–D) **only** if you read the figures; the basis the interface
   shows will be `curated-audit`. Leave `null` otherwise — an unassessed overlay is
   honest, a guessed grade is not.

3. **Write the brief** — append to `data/signal-briefs-en.json`, keyed by the
   automated record id (`recordId` in the queue):

   ```json
   {
     "id": "pubmed-12345678",
     "takeaway": "One sentence: what the paper adds, in plain English.",
     "caveat": "One sentence: where the evidence stops."
   }
   ```

   Note the key is the discovery-route record id, which leaves the window when the
   laboratory publishes newer papers — the overlay (keyed by canonical identity) is
   the durable layer; the brief improves the card while the record is visible.

4. **Promote to the paper layer only if earned.** A record read figure-by-figure that
   belongs in the corpus goes through `docs/RECIPE-bibliographic-migration.md` into
   `data/papers-en.json` with its attribution links. Do not shortcut this — the paper
   layer's contracts (verification depth, source registry, graph edges) are validated
   and mutation-tested.

5. **Validate**: `npm run check`. The data contracts, the CJK gates, the coherence
   rules and the manifest all run; a queue round that leaves the suite red is not
   done.

## After the round

- Commit the curated files together with a message stating what was read and to what
  depth. The next `npm run build:enrichment` run drops the covered records from the
  queue automatically.
- Records deliberately skipped need nothing: they simply stay in the queue as
  unassessed automated alerts, which is what they are.
